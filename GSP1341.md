# GSP1341 - Migrate from Cloud SQL for SQL Server to AlloyDB for PostgreSQL using Database Migration Service

This lab is almost all Console clicks. Cloud Shell is used once, only to print the values the lab text leaves blank. The SQL blocks are pasted into AlloyDB Studio or Cloud SQL Studio, not Cloud Shell.

Checkpoints (only three): Task 1, Task 3, Task 6. Tasks 2, 4 and 5 have no check button.

## Known lab traps/bugs (read first)

1. Region is blank in the lab text (shows as a line of underscores). Every DMS object (both connection profiles, the conversion workspace, the migration job) must use the region of your lab instance. Get it from the Setup block below or from the lab panel. Wrong region: `dms-pc` never appears and the checks score 0.
2. Start is slow. The Terraform setup takes up to 20 minutes. Do not begin until the AlloyDB cluster and instance both show Ready.
3. Destination profile uses the AlloyDB PUBLIC IP. Source profile uses the SQL Server INTERNAL IP. Swapping them makes the connection test fail.
4. `dms-pc` can take 5 to 10 minutes to appear in the Private connectivity dropdown. Close the Edit panel and reopen it until it shows. Create the destination profile first to use the waiting time.
5. Names are checked. Type them exactly: `alloydb-destination-profile`, `sqlserver-source-profile`, `sqlserver-to-alloydb-workspace`, `demo-migration-job`.
6. In the conversion workspace select only `dbo` and `guest`. Leave `cdc` unselected.
7. Lab typo in Task 6: the note says to wait if the count "is not 91". It should say 92. After the insert the correct count is 92.
8. Promote is one way. Do not click Promote until the job phase is CDC and the destination count shows 92.
9. The Promote checkpoint lags. The phase can take up to 10 minutes to reach Completed. Click the check only after that, and if it fails wait 30-60 seconds and click again.

## Setup (Cloud Shell, one paste)

Prints the region and the two IP addresses you need later.

```bash
gcloud config get-value project > ~/project
gcloud sql instances describe mssql-instance-skillsdms --format='value(region)' > ~/region
echo "PROJECT:"; cat ~/project
echo "REGION:"; cat ~/region
echo "SQL SERVER IPs (use the PRIVATE one in the source profile):"
gcloud sql instances describe mssql-instance-skillsdms --format='yaml(ipAddresses)'
echo "ALLOYDB IPs (use the public one in the destination profile):"
gcloud alloydb instances describe alloydb-instance-skillsdms --cluster=alloydb-cluster-skillsdms --region=`cat ~/region` --format='yaml(ipAddress,publicIpAddress)'
```

You should see: your project ID, a region such as us-central1, a PRIVATE address like 10.134.0.3, and an AlloyDB public address like 34.x.x.x. Write down the region, the SQL Server PRIVATE IP and the AlloyDB public IP.

If the AlloyDB command errors, skip it. The public IP is also offered in the Hostname dropdown in Task 3.

1. Console: View all products > Databases > AlloyDB for PostgreSQL.
2. Wait for Ready on both `alloydb-cluster-skillsdms` and `alloydb-instance-skillsdms`.
3. Click `alloydb-instance-skillsdms` > AlloyDB Studio.
4. Sign in: Database `postgres`, Built-in database authentication, User `dms`, Password `Welcome123#`.
5. Untitled Query tab, paste, Run:

```sql
CREATE DATABASE dms;
```

You should see: Statement executed successfully.

## Task 3. Connection profiles

Console: View all products > Databases > Database Migration > Connection profiles.

### Destination first

1. Create profile. Source engine: Cloud SQL for SQL Server. Destination engine: AlloyDB for PostgreSQL. Profile type: Destination.
2. Connection profile name: `alloydb-destination-profile`. Keep the auto ID. Region: your region.
3. Cluster ID: `alloydb-cluster-skillsdms`.
4. Hostname or IP address: click the box and pick the PUBLIC IP (34.x or 136.x), not the 10.x one.
5. Port `5432`, Username `dms`, Password `Welcome123#`. Continue.
6. Connectivity method: Public IP.
7. Run Test. Wait for "Your connection profile test was successful". Create.

### Source second

1. Create profile. Source engine: Cloud SQL for SQL Server. Destination engine: AlloyDB for PostgreSQL. Profile type: Source.
2. Connection profile name: `sqlserver-source-profile`. Keep the auto ID. Region: your region.
3. Under Define connection configurations click Edit.
4. Hostname or IP address: the SQL Server INTERNAL IP (10.x). Port `1433`, Username `sqlserver`, Password `Welcome123#`, Database `dms`.
5. Encryption Type: None.
6. Connectivity method: Private connectivity (VPC peering).
7. Private connectivity configuration: `dms-pc`. If the dropdown is empty, close Edit and reopen it every minute or so until it appears (trap 4).
8. Save. Run test. Wait for the success message. Create.

You should see: both profiles in the Connection profiles list.

Check my progress: Configure connection profiles for the source and destination instances

## Task 4. Conversion workspace

### Create and convert

1. Database Migration > Conversion workspaces > Set up workspace.
2. Name: `sqlserver-to-alloydb-workspace`. Keep the auto ID. Region: your region. Source: Cloud SQL for SQL Server. Destination: AlloyDB for PostgreSQL.
3. Gemini settings: turn ON Conversion assistance and Pattern matching. Leave Auto-conversion OFF for now.
4. Create workspace & continue. When prompted, Enable the Gemini for Google Cloud API.
5. Source connection profile: `sqlserver-source-profile`. Pull schema snapshot & continue. Wait a few minutes.
6. Tick `dbo` and `guest` only. Leave `cdc` unticked. Convert & continue.

You should see: a Conversion coverage percentage, roughly 86 percent.

### Tables

1. Left tree: expand `dbo` > Tables. Coverage moves to about 90 percent.
2. Conversion Issues tab > Issue tab. The repeated issue is "CLUSTERED INDEX is not yet implemented" (PostgreSQL has no clustered indexes).
3. Tick the header checkbox to select all eight > Mark as resolved > Mark all resolved.

### One view and one stored procedure (Gemini assist)

1. Left tree: Views > click one with an orange warning triangle, for example `Product_Sales_for_1997`.
2. Assist dropdown > Help me fix object conversion issues. Wait a few minutes.
3. Read the explanation > Insert suggestion > floppy disk icon > Save changes.
4. Repeat for one stored procedure with a warning, for example `CustOrderHist` or `Employee_Sales_by_Country`.

If the Assist option is missing, pick a different object that has the orange triangle. If none has a warning, skip this part. Auto-conversion below covers the rest.

### Auto-conversion

1. Above the AlloyDB draft pane click Gemini > turn ON Auto-conversion > Save settings > Convert.
2. "Conversion completed with issues" is safe to ignore.
3. Tick the Issue category and group header checkbox > Mark all resolved > Mark all resolved.
4. Conversion overview tab > left tree click Cloud SQL for SQL Server.

You should see: Conversion coverage 100%.

### Apply to destination

1. Top bar: Apply To Destination > Apply.
2. Destination Connection Profile: `alloydb-destination-profile` > Define & continue.
3. Tick the Filter header checkbox so every object is selected > Apply To Destination > Apply.

You should see: "Application to destination completed with no issues".

No checkpoint for this task.

## Task 5. Continuous migration job

1. Database Migration > Migration jobs > Create migration job.
2. Name: `demo-migration-job`. Keep the auto ID. Source engine: Cloud SQL for SQL Server. Destination engine: AlloyDB for PostgreSQL. Destination region: your region. Migration job type: Continuous.
3. Save & continue.
4. Source connection profile: `sqlserver-source-profile` > Save & continue.
5. Destination connection profile: `alloydb-destination-profile` > Save & continue.
6. Conversion workspace: `sqlserver-to-alloydb-workspace`. Tick the Filter header checkbox to select all objects > Save & continue.
7. Create & start job > Create & start.
8. Click `demo-migration-job`. Status goes Starting, then Running.

You should see: Phase changes from Full dump to CDC for the job and for every table. Wait for that before Task 6. Keep this tab open.

No checkpoint for this task.

## Task 6. Validate and promote

### Check the full dump (AlloyDB Studio)

Open a second Console tab. AlloyDB > `alloydb-instance-skillsdms` > AlloyDB Studio. Sign in with Database `dms` this time (not postgres), User `dms`, Password `Welcome123#`.

```sql
SELECT COUNT(*) FROM dbo.categories;
```

You should see: 8.

```sql
SELECT COUNT(*) FROM dbo.customers;
```

You should see: 91.

### Check CDC

Open a third Console tab. Cloud SQL > `mssql-instance-skillsdms` > Cloud SQL Studio (Database `dms`, User `sqlserver`, Password `Welcome123#`). Paste and Run:

```sql
INSERT INTO [dbo].[Customers] ([CustomerID], [CompanyName], [ContactName], [ContactTitle], [Address], [City], [Region], [PostalCode], [Country], [Phone], [Fax])
VALUES ('TEST1', 'Test CompanyName', 'Test ContactName', 'Test ContactTitle', 'Test Address', 'Test City', 'Test Region', '12345', 'Test Country', 'Test Phone', 'Test Fax');
```

Back in the AlloyDB Studio tab:

```sql
SELECT COUNT(*) FROM dbo.customers;
```

You should see: 92. If it still shows 91, wait a minute or two and run it again (the lab note has the number wrong, see trap 7).

### Promote

STOP: only continue once the count is 92 and the job phase is CDC.

1. Return to the migration job tab.
2. Top bar: Promote > Promote.
3. Wait for Phase to go from Promotion to Completed. This can take up to 10 minutes.

Check my progress: Promote the destination instance

If the check fails, confirm the phase says Completed, wait 30-60 seconds and click again.
